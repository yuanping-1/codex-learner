# 0.2.0 性能修订报告与本机复验交接

**日期：2026-11-05（北京时间）｜范围：JSON 正文完整性校验、提交性能与候选交付**

本轮已消除 JSON 回执在一次完整性遍历中的重复读取和哈希，保留写入前的历史完整性核验。云端同环境千份历史对比中，新提交中位耗时由 **1.174 秒降至 0.980 秒（减少 16.5%）**，P95 由 **1.387 秒降至 1.108 秒（减少 20.1%）**。候选新提交的最高进程内存为 **52.82 MiB**。

这是 Linux 合成样本结果，不能据此认定用户 Windows 的 20.5 秒问题已解决。重试的中位数略降，P95 增加约 5.8 ms，未观察到各项时延一致改善。**本机复验仍为 PENDING，完整交付保持 PARTIAL。**

## 1. 改动及保证

- JSON 正文一次打开、分块读取，同时核对实际长度和原始字节 SHA-256；验证后再严格解析。
- 保留非法 UTF-8、重复键、NaN/Infinity、路径、缺失和损坏检查；普通文本原答的换行、空白及 Unicode 路径保持。
- 一次遍历继续检查全部传递引用，并按既有引用身份去重。不引入跨事务缓存，不用大小/mtime 或抽样替代全文校验。
- 旧附件检查仍先于业务变更和备份轮换；原子替换、保存回读及幂等恢复顺序保持。
- 基准使用同一驱动、同一解释器和同一合成快照对比两套源码；每轮恢复独立副本。诊断探针与正式时延统计分开。
- 产品包和完整证据附件独立交付，历史证据目录不再被部分收录。实际 ZIP 校验后生成绑定其哈希的本机任务书。

课程格式仍为 schema 2，schema 1 只读兼容。教学业务 CLI 和原答/回执协议未改变。

## 3. 无探针时延与内存

| 操作 / 指标 | 基线 | 性能候选 | 变化 |

| 新提交中位数 | 1.173742 s | 0.980015 s | 减少 16.5% |
| 新提交 P95 | 1.386520 s | 1.107805 s | 减少 20.1% |
| 新提交最高进程峰值 | 52.57 MiB | 52.82 MiB | 增加 0.25 MiB，仍低于 256 MiB 初始目标 |
| 同 ID 重试中位数 | 0.097091 s | 0.092478 s | 减少约 4.8% |

每组 30 个正式样本均成功；重试没有新增记录，原答回读和上一有效清单检查均通过。小幅时延变化不能自动归因于代码，尤其不能忽略上升的尾部指标。下一步在目标 Windows 上按同样方法复验，不把旧单次 20.5 秒与本轮 Linux 0.980 秒直接作为加速比。

本次 Linux 新提交符合此前提出的中位数 2 秒/P95 5 秒体验目标；该目标仍未在用户目标机器确认，也不是已发布的 SLA。

## 4. 单独剖析与大正文内存

单独运行了 8 个诊断任务：每个版本、每种操作各 1 个无探针样本与 1 个带探针样本，全部成功。其耗时不加入前述 30 轮分位数。下表仅比较新提交的历史完整性阶段：

| 应用层计数 | 基线 | 性能候选 |
| --- | ---: | ---: |
| 附件文件打开次数 | 8,370 | 4,206 |
| SHA-256 创建/内容校验次数 | 6,288 | 4,206 |
| SHA-256 输入字节 | 3,676,775 | 2,879,635 |

候选在该阶段对全部 4,206 份唯一附件各打开、哈希一次，其中 2,082 份 JSON 不再重复读取。它不意味着整个事务中的回执回读等步骤不会再次访问附件。计数属于应用层，不能称为物理磁盘 I/O；探针阶段计时包含子阶段，不能相加当总耗时。

另用固定 8 份历史原答/评价，将正文从 **24,310 字节扩大到 134,225,678 字节（约 128 MiB）**：

| 操作 | 小正文峰值 | 大正文峰值 |
| --- | ---: | ---: |
| 列表 | 13.125 MiB | 13.125 MiB |
| 复盘摘要 | 13.000 MiB | 13.000 MiB |
| 新提交 | 13.625 MiB | 15.211 MiB |

清单仅从 36,327 增至 36,375 字节，所有操作低于 256 MiB。该结果支持正文扩大时日常内存保持轻量；新提交仍需读取历史正文，耗时由 0.020 秒增至 0.129 秒，不能把低内存等同于无 I/O 成本。

## 5. 验证与复现
