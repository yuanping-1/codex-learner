## 三类异常分别处理

### 调度单测的 mock 范围

本机独立诊断捕获到 `ver` 平台查询经过 `subprocess.check_output → subprocess.run`，进入了测试替换的共享模块函数，提前消耗模拟 worker 序号。证据解释这次测试失败，不解释自然 rename 错误，也不能补造此前 CI 的缓存状态。

仅替换测试中 `benchmark_restore` 自身的 subprocess 依赖引用，保留平台查询自己的真实调用路径。新增冷缓存及真实辅助 Python 子进程回归，验证元数据查询不算入四个模拟 worker，同时保留成功/失败/超时顺序及原始输出断言。没有修改真实驱动、预热平台缓存或放宽统计。

### 硬链接夹具能力

`os.link` 的 WinError 5 出现在夹具创建，后续产品拒绝硬链接断言没有执行。新测试将声明/同路径检查与真实硬链接检查分开；后者先在同源/目标目录对普通文件做一次能力探测。明确拒绝或不支持、且目标确认未出现时，仅该项 SKIP，覆盖仍是 BLOCKED；其他错误、目标出现但报错、或能力探测成功后归档链接失败继续 ERROR。产品的 samefile 检查未改。

这不将旧 ERROR 改成通过，也不把所有 PermissionError 都归为环境问题。无权限的真实 symlink/junction 分支同样继续保留 SKIP，模拟属性通过不替代真实分支。

### 自然发布失败：实际是部分释放残留

旧用例名 `test_release_failure_before_first_unlink_can_restore_matching_residue` 容易误读。它只在删除 `course.json` 前注入停止；按归档清单顺序，**此前已删除 15 个正文文件**。保留夹具恰好缺这 15 个成员，其余 24 个清单文件长度/哈希全部匹配。实际流程是部分释放后仍有课程清单，索引阻止普通读取，随后恢复在 `publish_course` 的 rename 抛出 WinError 5。

该次失败归档 SHA-256 为 `ede14f3b361e3f148dc63111598daf79151edce4662ed926061565b645494ea4`，39 个成员，`course.json` 的零基索引为 15。回滚恢复了残留，stage 随后清理；已有材料不是失败瞬间完整暂存副本。

保留该部分残留测试并准确命名为 `before_course_manifest_unlink`；另新增真正的 `before_first_manifest_member_unlink`，显式断言删 0 个、保留全部成员。两者都验证注入确实命中、实际删除前缀和残留哈希，再检查恢复后的文件。新增恢复前核验会改变时序，不能把其成功当作原自然失败已解决。

未找到可确认的自有普通流或 scandir 泄漏。固定 CPython 3.12.10 的 glob/walk 在 yield 前关闭 scandir；相关遍历在 rename 前已完成，解包/哈希/锁文件也有退出关闭路径。源码检查不替代现场句柄、共享模式或有效权限证据；外部进程、原生资源和过滤驱动等仍未确定。

## 新工具对准未覆盖的场景

`scripts/diagnose_archive_regression.py` 只运行两个打包的白名单用例，在新进程和持久合成夹具中启用既有回滚前探针：

- `--case partial`：真实测试的创建归档、核验、释放中断、保护检查与恢复全过程。
- `--case partial --archive <固定失败ZIP>`：先将本次失败归档的已核验成员布置到新本地库，再运行释放中断到恢复的链。明确跳过新建归档步骤，不能冒充完整创建生命周期。
- `--case full`：真正任何清单成员都未删除的残留分支。

默认 1 次，显式最多 10 次；每次新目录/新子进程，无自动重试，成功与失败的合成夹具都保留。记录实际安装模块、测试源码、驱动/探针哈希、UTC、PID、原始错误及 cause、前后文件状态。setup/seed 先于探针，早期和外部句柄不在其 Python 流覆盖内。测试断言、快照及探针都会影响时序，所有样本均为诊断，不加入无探针首调统计。

已有 60 次诊断仅覆盖空库和正常 release 后主要剩锁文件的状态，未覆盖本次正文已删但课程清单尚在的状态。新工具补充这一缺口；固定样本未出现自然失败时写“未捕获”，不追加样本直到出现期望结果，不关闭根因。
