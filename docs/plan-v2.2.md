# Codex 对话学习器实施计划

版本：v2.2。日期：2026-10-26。计划状态：本轮设计审查已完成；实现与运行验收待实施。本文替换上一版计划；原文及审查证据保存在设计阶段的 previous-plan.md 和 review.md（未纳入本仓库），修改对照在第五部分。

公开版本仅将个人目录替换为 %USERPROFILE%，并移除未随仓库发布的本机文档链接；原计划要求不变。

## 一 方案概要与确定的目标

采用本地 Skill、Codex 聊天教学、对话内交互面板和本地课程库。使用当前 Codex 会话组织教学与反馈；Python 负责确定性的记录操作，面板负责选择、输入和发起请求。第一版不引入独立模型服务、常驻 Web 后台或向量数据库。

| 已确认要求 | 实现约定 |
|---|---|
| 聊天配合交互面板 | 长讲解、公式和反馈在聊天正文；目录、题目选择、答案输入、续学和复盘入口在面板 |
| 理解并能应用，尽量按章节 | 优先沿用资料目录，学习目标覆盖解释、应用和适用边界 |
| 完整讲完再练习 | 默认先完成一章讲解，再进入章末练习；长章可分批，不强制穿插测验 |
| 围绕用户资料，也可补充 | 原资料为主；补充标明来源与用途，不能冒充原文 |
| 跨对话长期保存 | 同一电脑、可访问的固定课程库；新对话按课程记录恢复，不依赖旧聊天全文 |
| 用户控制节奏 | 支持直接看答案、跳过、换章、结束、补讲和手动复测；这些动作不自动证明掌握 |

通用学习器和真实课程分开。验收使用独立样例库，不污染个人学习记录。单人单机、多课程、按需生成章节、手动续学与复测为 v1 范围；云同步、提醒、自动间隔调度、多角色课堂不在本版内。

实施的第一关是：原生面板发送一份完整答案 → 记录脚本保存并回读 → Codex 给出回执 → 用户在不同工作目录的新对话中恢复该课程。该关未通过，依赖面板和跨对话能力的功能不得宣布可用。

## 二 学习行为与资料依据

### 资料导入与版本

接收用户明确提供的 PDF、DOCX、Markdown、TXT、可读取网页或聊天文字。附件和路径通过聊天交给 Codex；面板只给出导入入口说明，不假设它能上传文件或直接访问磁盘。旧式 DOC、加密文件和不可读取网页保留明确失败结果，提示需要转换、解锁或可读取副本。

本地文件导入时保存独立学习副本，记录原名称、导入时间、SHA-256 和读取范围；不移动或覆盖原件。聊天文字按原文保存。网页保存实际用于教学的可读取正文、可取得且必要的图表、URL、访问时间和定位信息；只有链接的条目不能标为已归档正文。无法保存或辨认的部分列为缺失，不承诺离线恢复未保存内容。

每份来源、每章讲义、题目及评分依据均有固定版本。正文用页码或小节定位，DOCX 用标题与段落/表格编号，网页用标题和摘录定位。扫描页、公式、表格、图注需要页面核对；无法核实的部分不能支持确定性教学或判题。原文事实、作者解释、补充和有争议的推断在相应段落区分。

导入采用“副本保存完成 → 内容读取核对 → 写入课程引用”的顺序。中途失败的临时文件不出现在正式课程目录。补充或更换来源只增加版本；已发布章节继续绑定旧版。用户要求采用新版时，展示受影响章节，生成新内容版本，旧作答仍属于旧版。新版本目标默认未评估，不自动继承旧版达标结论。

课程先形成完整目录、来源范围和每章学习目标，只生成当前章的详细讲义。没有反馈时可继续原计划，但不推断用户已理解；实际反馈用于调整后续解释深度和例子，不静默删除原定目标。

### 讲解与中断恢复

每章顺序为“目标与问题 → 必要前置 → 概念和机制 → 例子或推导 → 适用边界 → 小结 → 章末练习”。教学摘要和完整翻译是不同任务；用户明确要求逐句全文翻译时保留原文顺序与覆盖范围，不能用教学摘要替代。

讲义分成有稳定编号的连续片段，每片段记录来源范围。正式记录只声称可证实的事件：讲义文件已准备、某片段待讲、用户确认的续学位置、用户要求跳过。没有可靠的“用户界面已完整显示”回执时，不维护伪精确的“已呈现”游标。

发出一段讲解前保存待讲片段。面板将“续讲本段”和“本段已读，下一段”区分；只有后一动作，或“已读到第 N 节”等明确表达，才确认对应位置。普通“继续”用于恢复尚未确认片段，不能自动确认整段；课程或片段不唯一时先选择。确认请求绑定 course_id、chapter_id、content_version、part_id；重复确认同一片段不再推进，不确认未提供的后续片段，不回退已确认范围。旧面板的确认若不再对应当前待讲片段，返回该片段已有状态，并提供明确切换入口。续学确认只用于定位，不表示读懂。

中断后从最后可靠检查点恢复，最后一个未确认片段可以重讲；不越过未确认范围。默认“开始练习”在所有片段已确认后可用；仅余末段待确认时，入口明确写为“末段已读，开始练习”，一次确认末段并进入练习。用户明确要求跳过讲解可以进入练习，但剩余范围记录为跳过，不标为讲解完成。用户提前直接回答已知题目时可保存答案，不因此自动改变教学阶段。

### 练习与反馈

题量由学习目标和所需证据决定，不固定为三题。每章默认覆盖解释、应用、边界三类任务；不适用的类型说明原因，未检验目标仍为未评估。每个目标分解为有稳定 check_id 的必要检验项，题目明确关联一项或多项，评价逐项给出。

讲义、来源和学习目标使用 content_version；题目使用 question_id 与 question_version，评分依据使用 rubric_version。增加练习或手动复测的新题只增加新的 question_id，可以绑定当前内容版本及既有检验项，不使已有学习记录失效。修改已有题目升级 question_version；修改来源、讲义的实质内容或目标结构才建立新 content_version。发布题目新版后，旧题版本的评价只供历史回查，不再支持当前结果；其他未改题目的有效证据继续保留。受影响检验项依据其余合格作答重新汇总，没有合格作答时显示“未评估，题目已改版”。

题目交给用户前，保存绑定该内容版本的评分依据：目标、必要判断点、可接受的替代答案、关键错误、来源位置和参考解释。评分依据与来源核对后才作为正式题目发布；无法确定答案的题目可以用于讨论，但不用于确定性达标判定。面板初始内容不携带参考答案和评分细节，答案通过明确请求后在聊天解释。

原始答案先落盘，状态为“答案已记录，反馈待生成”；随后评价、补讲并保存反馈。生成反馈时中断，恢复时处理原来的待评价答案，不要求用户重新输入。反馈按原答逐项说明成立之处、错误、遗漏、前提及依据，允许不同措辞和合理的替代推理。

帮助记录包括用户声明的帮助、主动请求，以及反馈/补讲中针对该题登记提供的实质提示或完整解法。一般讲义学习不自动算作具体题目的提示。保存反馈时同时标明 none、hint 或 solution 及对应题目；发出提示或解法前登记 HelpEvent，不依赖用户是否主动请求。事件只证明请求或提供已登记，不证明用户实际阅读；输出中断后仍保留该记录。

接收原答时，按此前相关事件保存原始帮助快照，后来的反馈不能反向改写这份原始快照。主动请求在提交答案之后发生，只影响后续同题作答；同题已登记的提示或解法按 question_id 继承，更新题目文字或重新作答不能清空。新的情境题使用新 question_id，独立记录并注明前序教学背景。界面使用“本次未记录帮助”“有提示记录”“有完整解法记录”，不声称排除了外部帮助。宿主请求取消且未进入对话时不产生正式帮助事件。仅指出错误位置的反馈不一律标为完整解法。

用户事后明确补报“作答前已用过帮助”，作为帮助更正事件关联 target_submission_id，保留原快照、真实登记时间及补报原因，不伪造早期事件顺序。当前有效帮助程度根据原快照与更正计算，重新汇总受影响结果；该明确补报以目标作答为起点，影响此后同一 question_id 的作答，不影响其他题目。若补报指向不明，先明确是哪次作答。用户只是现在才索要解法，不据此更正此前帮助程度。

每次作答为所覆盖检验项保存“符合依据、需补强、待核实”和帮助程度。当前结果先筛选候选：同一课程、章节、当前采用的 content_version 和对应题目当前适用的 question_version，且 evaluation_scope 为 current；排除 pending_content_review、history_only 及已失效题目版本。评分依据失效的当前作答仍参与顺序选择，但结果必须显示待重评，不能回退取更早的通过结果。随后按三步确定：沿更正关系得到每条 Submission 的有效评价；对每个 check_id，按 Submission 首次保存时的 received_revision 选择最新候选作答；最后按必要项汇总目标。反馈或更正生成时间不改变作答先后，旧作答的晚到反馈不能抢占新作答。最新作答待评价时显示“新作答待评价”，此前结果只能作为注明时间的历史参考。

每个检验项：正确且未记录帮助为“本次练习达标”；正确但有帮助为“在帮助下完成，待独立检查”；错误为“待补强”；判断或依据不确定为“待核实/待重评”；没有作答为“未评估”。不同检验项不相互覆盖。目标只有全部必要项均满足未记录帮助的有效通过条件，才显示本次练习达标；其余情况展示各项状态与已达标项数，不强行压成一个含糊标签。章节汇总同理，不生成掌握百分比，不推断长期掌握。手动复测另记时间间隔和题目，延迟与新情境结果单独展示。

评分应用错误的更正保留原答案、原反馈、更正理由及修订关系，只替换其所属 Submission 的有效评价，不改变 received_revision。评分依据本身确认有错时，发布新 rubric_version 并明确受影响题目/检验项；同一原子操作将依赖错误依据的评价标为待重评，即使重评尚未进行，也不能继续作为当前达标证据。未受影响项保持原状，历史仍可回查。

仅纠正相同题意与目标下的评分依据，可以保持 question_version 和 content_version 不变，并在原 Submission 上按新依据追加评价。若纠正改变题意，升级 question_version；改变来源、实质讲义或目标，则建立新 content_version，按新内容处理。进入复盘时逐条处理待重评项，不新增自动批量重评服务。

## 三 保存与交互接口

### 入口与权威记录

入口名为 codex-learner，支持明确选择该 Skill 和“打开学习器”“继续某课程”等自然语言。新技能目标目录为 %USERPROFILE%/.agents/skills/codex-learner；这是官方列出的用户级位置，仍须实测新对话发现与调用。安装时只处理该技能，目标已存在则先比较与保留原版，不修改全局配置。[官方技能发现规则](https://learn.chatgpt.com/docs/build-skills)

正式课程库为 %USERPROFILE%/Documents/Codex/2026-10-26/codex/outputs/learning-library。技能配置保存绝对根路径；不得因新聊天工作目录不同而创建另一套同名库。库不可访问时报告原路径与具体错误，不静默新建空库。多个候选课程只说“继续”时展示选择。课程库由用户持有，可备份；不写入 Codex 的正式记忆库。

每门课程一个权威 JSON 状态文件，来源副本和讲义为不可静默覆盖的独立文件。课程列表从各课程状态提取，导航索引如有缓存必须可重建，避免维护另一份权威进度。Markdown 是讲义与复盘输出，不把人工修改的摘要自动当成正式作答。

| 对象 | 必需信息 |
|---|---|
| Course | course_id、标题、目标、章节顺序、来源版本引用、当前学习位置、state_revision、schema_version |
| ChapterContent | chapter_id、content_version、来源定位、片段范围、目标及带 check_id 的必要检验项 |
| Question | question_id、question_version、所属 content_version、题干、覆盖的 check_id、适用 rubric_version |
| LectureCheckpoint | 当前内容版本、待讲 part_id、已确认范围、明确跳过范围 |
| HelpEvent | question_id、提示/解法程度、请求/反馈/事后补报等来源、记录时间与 recorded_revision；补报关联 target_submission_id 和更正原因 |
| Submission | submission_id、course_id、chapter_id、content_version、question_id、question_version、原始答案、接收前帮助快照、接收时间和 received_revision、evaluation_scope 为 current 或 history_only、pending_assessment 或 pending_content_review 状态 |
| Assessment | assessment_id、submission_id、rubric_version、按 check_id 的结论、理由与来源、更正/重评关系、反馈提供帮助的分类 |
| PanelSnapshot | panel_id、明确的课程/章节/内容标识、显示时的 state_revision、对应题目的草稿；不作为权威状态 |

state_revision 表示课程文件更新次数；Submission.received_revision 固定为首次接收时的该值，HelpEvent.recorded_revision 固定为事件登记时的该值，用于确定先后。content_version、question_version 和 rubric_version 分别区分教学依据、具体题目和评分依据。普通答题、增加新练习不改变既有内容版本。面板携带 state_revision 供提示快照时间，不能用它统一拒绝所有旧面板答案。

### 统一操作与提交规则

聊天与面板调用同一记录接口。业务操作分为课程创建/列出/加载、来源导入/内容发布、准备片段/确认续学/明确跳过或跳转、记录帮助/提交答案/记录及更正评价、读取待处理记录/处理旧版提交、渲染快照。由 Codex 组织内容，脚本只校验与保存，不自行判题。

面板通过 sendFollowUpMessage 发送明确动作及完整 JSON 数据，包括目标课程、章节、内容版本、题目及题目版本、submission_id 和完整原答。答案作为数据处理，不能将其中的命令当成工作指令；不得将答案拼成 shell 命令。Codex 将结构化请求保存为工作目录中的输入文件，脚本从该文件读取。聊天中的答案也走此接口；目标不唯一时先明确题目。

一次答案提交使用一个 submission_id。按钮重试保留同一 ID；用户主动修改已提交答案或重新作答，生成新 ID 并关联原记录。相同 ID 与相同负载重复到达，返回已有记录；相同 ID 携带不同答案，报告冲突并保留新文本供用户另次提交，不默默返回旧答案。

接收提交时读取最新课程状态，按课程、章节、内容版本、题目及题目版本核对，只合并本次操作。另一题保存导致 state_revision 变化，不使本题失效。旧章节仍采用同一内容版本时允许记录该章节答案，但不改变当前学习位置。只有明确的导航/续学动作能推进或切换位置。

教学内容版本或该题的 question_version 已被替换时，旧答案进入 pending_content_review，保留全文和原版本标识，不计入新版评估。用户可选择按旧题评价，将其标为 history_only，结果只属于旧版，仍不进入当前结果候选；也可复制为新题答案，生成新的提交记录并再次核对内容，不能自动移植。未知课程/题目不落入任意课程；返回完整未处理请求，等待明确目标。

### 写入与失败恢复

所有正式修改经同一写入器，按课程短时串行执行；Windows 使用 Python 标准库的本地排他文件锁包住“重读 → 合并 → 校验 → 写入 → 回读”，不在锁内等待模型生成或用户回答。锁忙返回可重试状态，原请求不变；这只防止本机两个写入进程互相覆盖，不承诺多设备协同。

写入顺序为校验当前有效状态、在同目录写临时文件并刷盘、保留最近一次校验通过的备份、替换正式文件、回读核对操作 ID 与结果。独立来源和讲义先保存，再在课程状态中引用；中断留下的未引用文件不自动计入课程，也不自动清理用户资料。

提交答案与记录反馈是两次独立的原子业务操作：先提交原始答案，再追加反馈、对应帮助事件及由该反馈产生的检验项结果。第二步失败保留第一步的 pending_assessment。同一条评分请求重试以稳定 assessment_id 去重；同一 ID 改变内容视为冲突，更正必须生成新 ID 并引用原记录。

状态替换后回读失败或回复中断，结果可能已保存；重试先查相同 ID，确定现状后再返回回执，避免再次计数。真正写入失败时保留已有有效课程；若本机写入仍可用，保留输入请求文件；磁盘不可写时只能保留当前聊天/面板中的文本并明确提示另存，不能保证所有未保存草稿永久不丢失。

发现状态损坏或未知 schema_version，不静默重置或降级。展示问题和最近有效备份；保留损坏文件供核对，恢复备份需用户选择，恢复后明确可能缺失的时间范围。v1 没有既有课程数据迁移任务；未知版本拒绝修改。

### 面板与保存状态

面板是独立文件快照，生成新面板使用新 panel_id 和路径。历史面板保留其内容版本，不假装随当前记录同步。顶部显示快照对应课程、章节和记录时间；下方为目录、当前操作和复盘入口。复杂讲解和长反馈留在聊天。

每个题目使用有标签的原生输入框。未提交草稿只能尽力恢复：widgetState 全量快照小于 16 KiB，在有意义交互后保存，不在加载和状态事件中再次保存。草稿绑定课程、题目和内容版本。超出缓存预算时不截断作答，只停止缓存并提示复制或在聊天提交；完整答案仍须进入后续消息。消息长度被宿主拒绝时保留草稿，提示改为聊天或附件提交，不自动分割成多次作答。

面板本身不能 fetch 外部接口或写本地课程文件。原生请求被取消时保持草稿；发送失败时提供完整可复制操作文本作为恢复途径。恢复途径不能代替原生回传验收。

| 可显示状态 | 依据 |
|---|---|
| 草稿 未正式保存 | 只有输入或宿主尽力缓存 |
| 请求已发起 等待处理 | 调用了宿主接口；不能据 Promise 成功宣称落盘 |
| 答案已记录 反馈待生成 | Python 回读确认 Submission，Codex 返回对应回执 |
| 反馈已记录 | 回读确认 Assessment，返回新面板及聊天反馈 |

旧面板无需异步更新为“已保存”。正式回执在新回复及新快照中体现，列出课程、题目、提交 ID、记录时间和处理状态。即使已有反馈记录，输出被中断也可按记录重新显示，而不重新评分。

使用宿主现有布局与主题工具，736 px 常规宽度并支持 320 px；检查明暗主题、键盘操作、文字放大、长中文标题和长答案。保留可见焦点与必要状态文字，不只用颜色表达；不添加固定高度的外层滚动框。面板只放必要题干、标签和操作；长题干完整显示在聊天并用题号对应。

## 四 实施顺序与验收

以下是本地计划中的实施单元，不是已经发布的外部工单。每个单元完成一条可演示路径。验收使用隔离样例根目录；正式库与样例库不能共用。

| 单元 | 前置 | 可演示交付 |
|---|---|---|
| T0 宿主提交与新对话恢复 | 无 | 最小 Skill、一门样例课程、一题面板；原生回传完整答案，保存回读，返回回执；用户打开不同工作目录的新对话，发现入口并恢复同一记录 |
| T1 从资料建立课程 | T0 | 导入副本、来源定位、章节目标、目录与当前章；资料缺失有明确状态；原文件移动后已归档内容可读取 |
| T2 整章讲解与中断续学 | T1 | 分段讲解、对应确认、未确认片段恢复、明确跳过；默认章末才练习，跳过不变成已讲 |
| T3 练习反馈与复盘 | T2 | 预存评分依据、原答先保存、后生成反馈、帮助记录、目标覆盖、评分更正、手动复测 |
| T4 旧面板与失败恢复 | T3 | 同面板多题、重复请求、内容改版、写入/回读/反馈中断、损坏记录恢复，完整保留已确认记录 |
| T5 多课程与资料更新 | T3 | 课程选择不串写，旧章答题不换当前位置，新来源版本不继承评估，不同工作目录恢复多课程 |
| T6 安装包与综合验收 | T4、T5 | 安装与重启后调用、两章学习全过程、素材格式覆盖、布局与输入检查、验收记录及备份/恢复说明 |

T0 必须验证真实 Codex 宿主；独立 HTML 预览只辅助检查界面。新对话由用户实际打开并调用，不擅自创建新聊天。入口发现、文件访问或回传不可用时记录失败点，不发布“可用版本”；可独立继续来源与数据规格工作，不能把外部网站或另一个模型服务当成已满足原目标。

每个正式写入的完成标准是记录回读；每个教学步骤的完成标准按对应事件及来源覆盖核对。以下全部是实施阶段待执行的验收，计划审查不将它们标为运行通过。

| 编号 | 场景 | 必须观察到的结果 | 负责单元 |
|---|---|---|---|
| E01 | 原生提交，含中文、多行、引号、代码样文本 | 原答逐字一致，恰好一条记录和可核对回执 | T0 |
| E02 | 宿主确认取消或发送失败 | 无正式提交；草稿仍在当前界面，可复制恢复 | T0 |
| E03 | 用户新开不同 cwd 的对话 | Skill 实际可发现，读取固定库，恢复同一题及原答；无旧聊天全文也可继续 | T0 |
| E04 | PDF、DOCX、MD、TXT、网页样例导入 | 各格式来源定位可核对；图表/扫描页不可读则显式缺失，不假造内容 | T1 |
| E05 | 移动原文件或网页变化 | 已归档内容与原校验值一致；未归档部分显示缺口 | T1 |
| E06 | 输出前或输出中中断后仅说继续；重复/旧片段确认 | 普通继续不确认整段；明确确认绑定片段且只推进一次，旧确认不回退或越级 | T2 |
| E07 | 完整讲解、提前跳过、明确结束 | 默认章末练习；用户跳过按跳过记载，结束不新增完成事件 | T2 |
| E08 | 正确、部分正确、错误、不知道、争议和同义改写 | 按预存依据评价；关键词齐全但因果错误不能过关，合理替代答案不机械判错 | T3 |
| E09 | 主动提示、正常反馈给解法、同题重答 | 原答不被后来反馈反向污染；后续同题继承提示/解法记录，不能冒充独立通过 | T3 |
| E10 | 同目标两项分别作答，后续仅重做其中一项 | 各项证据独立保留；一项未做或失败时不判目标达标，另一项不被覆盖 | T3 |
| E11 | 原答落盘后反馈生成中断 | 恢复 pending_assessment，从原答继续，无需重新输入、不重复计数 | T3 |
| E12 | 同一旧快照连续提交 Q1、Q2 | 两题均接收，不因另一题使 state_revision 改变而拒绝 | T4 |
| E13 | 相同 ID 重试与相同 ID 不同负载 | 相同请求返回原记录；不同负载报告冲突，不能静默吞掉新答案 | T4 |
| E14 | 当前在第二章，第一章旧面板提交 | 记录第一章答案，当前章节仍为第二章；新版题目不接纳旧版评估 | T4 |
| E15 | 原子替换前失败、替换后回读失败、锁忙 | 前者原文件有效；后者按 ID 核对实际结果；锁忙保留原请求可重试 | T4 |
| E16 | 主状态损坏、缺失、未知 schema | 不新建空课程冒充恢复；备份恢复经选择，保留损坏原件并说明差异 | T4 |
| E17 | 多课程同名、笼统继续、相同题号 | 选择稳定课程 ID，不按标题猜测或跨课程写入 | T5 |
| E18 | 导入同一来源新版并采用新章节 | 旧资料、讲义和作答仍可回查；新版目标不自动达标 | T5 |
| E19 | 320/736 px、明暗主题、放大、键盘、超长输入 | 内容可操作，无遮挡；缓存超限不截断原答，状态标签真实 | T6 |
| E20 | 两章学习到复盘、关闭后恢复、手动复测 | 按课程状态完成全过程；活动、帮助、评估、延迟检查分别记录 | T6 |
| E21 | A 后提交 B，B 先评分，再补评或更正 A | 当前对应检验项按 B 的接收顺序取值；A 更正只更新其历史，最新待评答案明确显示待评价 | T3 |
| E22 | 已达标后发现评分依据错误，仅修正评分标准 | 受影响项立即待重评，不影响其他项；相同题意可保留内容版本，复评保留修订关系 | T3 |
| E23 | 当前章新增复测题或修改已有题 | 新题不作废其他题；旧题改版后原版评价退出当前候选，仅受影响项重新汇总，无合格证据则未评估 | T5 |
| E24 | 已达标后补报作答前看过参考答案，对照现在才索要解析 | 补报保留原快照、追加更正并调整该次及后续同题的有效帮助；现在索要不反向污染此前作答 | T3 |
| E25 | 新版 B 已评分，旧版 A 晚到并选择历史评价 | A 的 pending_content_review 或 history_only 均不抢占 B；历史评价与当前结果可分别查看 | T4 |

T6 全部通过支持“可供个人试用”。长期保持与迁移效果只能来自后续真实学习证据；不使用软件测试推导学习效果，也不以尚未开展的长期实验无限阻塞软件交付。

### 现成方案的采用边界

仅借鉴设计不复制上游实现。实施中若确需复制代码，固定版本、核对许可证并保留声明；不能把上游维护状态和演示效果当成本地验收。

主动回忆和概念推断参考 [Karpicke 与 Blunt 2011](https://learninglab.psych.purdue.edu/downloads/2011/2011_Karpicke_Blunt_Science.pdf)；反馈与教学调整的组合参考 [ASSISTments 2016](https://journals.sagepub.com/doi/10.1177/2332858416673968)。[Kestin 等 2025](https://www.nature.com/articles/s41598-025-97652-6)支持精心设计的 AI 导师在其本科物理实验中的即时学习收益，不能外推长期保持。[Bastani 等 2025](https://www.pnas.org/doi/10.1073/pnas.2422633122)显示有 AI 时答题表现可以与撤去帮助后的表现分离，因此保留帮助与独立检查的区别。“整章讲完再练”是用户偏好，不包装为已证明最优的节奏。

此前 2026-09-27 至 2026-10-26 的近 30 天补查限于 GitHub 公开发布与问题样本；[OpenMAIC 中断恢复问题报告](https://github.com/THU-MAIC/OpenMAIC/issues/2020)用于提出失败场景，不作为本机已复现的证据。日常运行不要求加载本轮全部规划技能。

| R12 补充 | 目标结果与评分更正的更新方式未定 | 必要项逐项评估，保留更正关系，当前视图采用有效记录 | 使复盘、重试和更正结果一致 |
| R13 替换 v2.0 | “当前目标摘要取当前内容版本下最近一条有效评估” | 先取每条作答的有效评价，再按接收顺序逐 check_id 取证据，最后汇总目标 | 后补旧反馈不能抢占新作答，一题不能覆盖整个目标 |
| R14 补充 v2.0 | “原作答可回查并重新评价” | 错误依据关联结果立即待重评，仅受影响项失效；保持题意的更正不必改内容版本 | 已知错误的达标结论不能继续有效 |

| R16 补充 v2.0 | “请求提示或答案后记录该事件” | 反馈/补讲的提示和解法同样登记；以原答接收前事件形成帮助快照 | 正常反馈泄露答案后重答仍受到帮助 |
| R17 补充 v2.0 | content_version 同时承担教学内容和题目版本 | 增加新题不改变原教学依据；修改旧题、修改评分依据各有对应版本 | 手动复测不应重置整章评估 |
| R18 补充 v2.1 | “帮助程度按原答接收前的相关事件确定” | 保留原始快照，允许用户事后补报先前帮助，并关联作答追加更正 | 真实的新信息必须能纠正独立完成的误记 |
| R19 补充 v2.1 | “对每个 check_id…选择最新作答”未在该段落实版本筛选 | 先筛课程与内容/题目版本及评价范围，再比较作答顺序；题目改版退出旧题证据 | 晚到的旧版作答及历史评价不能抢占当前结果 |
