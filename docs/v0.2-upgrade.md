# 0.2.0 迁移、低内存解析与历史归档

本版保持一个可写课程清单、课程锁和原子替换，不引入数据库或常驻服务。下面命令中的 `learner.py` 需替换为实际安装的绝对路径，并使用配置的 Python。全局 `--library` 只覆盖库位置，仍可显式 `--config` 选择 OCR/Drive 配置。

## 配置与诊断

```json
{
  "schema_version": 1,
  "library_root": "C:/Users/you/Documents/Codex/learning-library",
  "python_executable": "C:/Python312/python.exe",
  "memory": {"core_target_mb": 256, "ocr_limit_mb": 2048},
  "ocr": {
    "profile": "rapidocr",
    "memory_limit_mb": 2048,
    "timeout_seconds": 300,
    "python_executable": "C:/Users/you/AppData/Local/CodexLearner/ocr/venv/Scripts/python.exe",
    "model_dir": "C:/Users/you/AppData/Local/CodexLearner/ocr/models",
    "model_manifest": "C:/Users/you/AppData/Local/CodexLearner/ocr/models/models.json",
    "cache_dir": "C:/Users/you/AppData/Local/CodexLearner/ocr/cache",
    "worker_lock": "C:/Users/you/AppData/Local/CodexLearner/.ocr-worker.lock"
  },
  "drive": {"directory": "G:/My Drive/CodexLearnerArchives"}
}
```

`install_ocr.py` 生成实际路径，不必照抄示例。先配置官方 Drive 客户端为流式模式，选择私有目录，不将整个历史目录设为离线。模型、环境、活跃库和最近备份放在普通本地盘。

```text
learner.py doctor
learner.py list
```

doctor 报告版本、实际 Skill/Python/库路径、安装清单 SHA-256 及不匹配文件、解析器、模型校验、缓存磁盘空间、运行任务和 Drive 配置。路径可访问仅表示本地目录可访问，`cloud_sync` 保持未确认。

## schema 1 迁移

安装器不自动迁移。schema 1 可只读查看，写入返回 `migration_required`；已登记操作的相同请求仍可返回原回执。先预览：

```text
learner.py migrate --course COURSE_ID --preview
learner.py migrate --course COURSE_ID --expected-sha256 PREVIEW_ORIGINAL_SHA256 --confirm
```

第二条用于已经选择迁移的课程。预览报告原文件哈希、原/新清单大小、原答和操作数量及容量检查。执行在旁路目录用 ijson 增量解析，将正文落为不可变文件，校验关联与哈希，保留旧清单和上一有效版本后原子切换。原 ID、时间、接收修订号、帮助快照、更正关系和操作指纹不变；原答 CRLF、空白和 Unicode 不归一化。

`migration-backups/<旧哈希>/` 保留旧字节和报告。旧 `verified` 作为 `legacy_verified` 历史声明保留，新 `verified=false`；实际重新核对后用 `verify_source` 追加绑定来源与正文哈希的事件。不要把历史讲义当成新核验结论。

普通清单读取有容量门槛；大旧库直接走流式迁移。迁移仍对单个 JSON 标量设 16 MiB 安全上限，超限明确拒绝并要求经审核的拆分转换，不先全量加载。迁移另设保守的元数据内存估算上限，达到预算就提前停止。正文和备份引用的文件不回收；损坏或缺失时拒绝恢复，不返回空内容。中断留下的未引用不可变文件不自动删除。

## 定向读取、复盘与导出

```text
learner.py show --course COURSE_ID
learner.py read --course COURSE_ID --submission SUBMISSION_ID
learner.py read --course COURSE_ID --source SOURCE_ID --locator page:3
learner.py read --course COURSE_ID --chapter CHAPTER_ID --part PART_ID
learner.py read --course COURSE_ID --question QUESTION_ID --question-version qv1
learner.py history --course COURSE_ID --page 1 --page-size 20
learner.py history --course COURSE_ID --page 1 --include-bodies
learner.py retests --course COURSE_ID --kind delayed
learner.py export --course COURSE_ID --output C:/Exports/full-course.json
```

`show` 返回紧凑清单，不能再期待内嵌全部原答。列表/复盘默认只读元数据；`read` 读指定正文并验哈希。历史按页加载，区分 immediate/delayed/transfer 及无法可靠分类的旧复测。完整 JSON 导出写入文件，不一次性展开全文；它用于阅读，完整恢复请用闭合 ZIP 归档。

写入前会流式校验历史正文，保护最后有效备份。因此内存不随历史正文同步增大，但提交耗时仍随历史总字节数增加；本版没有宣称写入时间与课程大小无关。

## OCR

默认 2048 MiB 是 OCR 进程组预算。Windows 使用 Job Object 限制提交内存，另外记录工作集/RSS 峰值；其他平台的 RSS 监控与 Windows 提交内存硬限制分别报告。可用内存不足、超时、模型或输出损坏时明确停止。启动前要求可用物理内存至少为所选 OCR 预算加 256 MiB 核心预留，不足时不启动模型。不得自动增加预算或以降低清晰度冒充核验通过。

扫描页逐页处理，正文、坐标、原页号、旋转和渲染几何信息保存。RapidOCR 和 Docling 共享一个工作锁，阻止跨课程同时加载多个模型；工作进程结束释放模型。重试相同输入/config 自动沿用检查点；检查点根据原件和模型哈希绑定，失配不能复用。公式保留原图定位，须核对后转录；默认不加载公式生成/图片描述模型。

导入接口的 profile、page_range、memory_budget_mb 与 resume 等字段见 [操作接口](../skills/codex-learner/references/operations.md)。复杂页 Docling 只接受明确选页和独立离线模型清单；它是可选、待平台验证的能力，超预算保留待核对。

## Google Drive 历史归档

### 生成与复制

```text
learner.py archive-create --course COURSE_ID --output C:/Archives/course-r42.zip
learner.py archive-check --archive C:/Archives/course-r42.zip
learner.py archive-copy --archive C:/Archives/course-r42.zip --drive-directory "G:/My Drive/CodexLearnerArchives"
```

包包含当前/上一有效清单、迁移备份及所有可达原件、讲义、作答、评价、帮助、核验和操作回执正文。清单记录相对路径、字节数和 SHA-256，ZIP 外另有 `.sha256`。只捕获课程数据，不收配置、凭据、模型、缓存；打包和校验逐块处理。写入同步目录仅返回 `sync_unconfirmed`，并登记此目录避免把它误作网络取回证据。

### 网页取回与明确释放

等待官方客户端显示同步完成。**在 Drive 网页下载该 ZIP 到独立普通本地验证目录**，不要从流式盘或本地缓存复制代替。随后：

```text
learner.py archive-confirm-download --archive C:/Archives/course-r42.zip --download C:/DriveDownloads/course-r42.zip --sha256 ZIP_SHA256 --source-declaration web_download --output C:/Archives/course-r42.download.json
learner.py archive-release --course COURSE_ID --archive C:/Archives/course-r42.zip --verification C:/Archives/course-r42.download.json --confirm
```

核验要求独立文件，拒绝原路径、硬链接、登记过的 Drive 目录以及配置缓存目录。哈希证明包内容一致；网络来源仍明确为 `user_declared`，不能称为程序自动观测到上传/下载。

`archive-release --confirm` 仅用于用户明确决定释放的历史课程。程序再次核验下载包和当前快照，检查待评价、待重评、运行任务及未归档文件；任何失败都不推进正常删除。释放先持久保存轻量归档索引，再移除已经确认入包的课程数据，断电中断可从同一校验包恢复。索引保留已登记的 Drive 包位置。它不删除用户原始资料、OCR 模型或 Drive 缓存；指定输出位置的本地 ZIP 和网页下载副本也保留。若要实际释放这两份占用，确认 Drive 副本可用后由用户另行删除这些本地文件，不要删除 Drive 中的归档。

### 按需恢复

```text
learner.py archive-list
learner.py archive-restore --archive C:/DriveDownloads/course-r42.zip --sha256 ZIP_SHA256 --confirm
```

先落本地暂存、核验 ZIP/成员哈希、安全解包和正文闭合，再启用课程。同 ID 已存在时拒绝覆盖，显示冲突后可恢复到另一个明确选择的本地库。恢复完成后继续学习不依赖 Drive 在线。断网不影响活跃课程；云端尚未取回的历史课程显示需要恢复。

导入和打包运行时使用任务标记阻止并发释放；进程中断后重试同一导入 ID 可以继续。若不再继续，先用 doctor 检查任务；确认进程已经退出后可执行 `task-cleanup --course COURSE_ID --task MARKER_NAME --confirm`，只清标记，不删课程或检查点。活进程的标记无法清除。

上传失败、配额不足、磁盘不足或校验失败时保留本地课程。Drive 缓存只通过官方客户端管理，不直接删除尚未同步的缓存。整门课程是首版归档单位，不从活跃课程中零散移走正文。

## 验收边界

自动化测试使用隔离临时库。资源结果必须分别列核心、OCR、Codex、Drive；没有访问到的进程填未测，不能用 OCR RSS 代表整机。10/100 页规模、三个连续文件、长期记录压力、故障恢复和最终安装包验收结果见 [验收记录](acceptance-v0.2.md)。真实 Codex 两章教学、Windows 干净安装和实际 Drive 取回需单独保留证据，不能由模拟测试替代。


## 资源基准命令

以下命令只建立临时合成库，不接受正式个人课程库；构造和测量使用不同进程，避免构造阶段的高水位污染日常内存：

```text
python scripts/benchmark_memory.py --output artifacts/memory-benchmark.json
python scripts/benchmark_history.py --output artifacts/history-benchmark.json
python scripts/benchmark_migration.py --output artifacts/migration-benchmark.json
```

OCR 基准脚本使用明确提供的离线 OCR 配置，自己生成中英数字扫描页，不自动联网下载模型：

```text
python scripts/benchmark_ocr.py --help
```

Native PDF 无 OCR 配置时的普通文字读取有文档/提取限额，但没有宣称每个第三方解析器内部的单次分配都受核心硬内存限制；核心 256 MiB 是下列日常记录操作的实测目标，不是对任意复杂文件的保证。Docling 内部布局模型也不因预览图限制为 300 万像素而自动满足相同栅格上限，仍由独立进程的总体预算控制。
