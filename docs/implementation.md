# v2.2 的当前实现

开发在 Linux 云环境，运行目标为用户本机 Codex。原始计划完整保留于 [plan-v2.2.md](plan-v2.2.md)。本版为 0.1.0 验收候选，Windows 43 项核心测试、E01 原生特殊文本保存和 E03 新对话恢复均通过。2026-11-04 正确修订已在本机生效，原生警告清除、取消与重试提示通过，配置及库内 10 个文件不变。真实发送失败恢复和综合教学验收仍未完成。详见 [最新本机验收证据](local-ui-acceptance-2026-11-04.md)。

## 结构

- skills/codex-learner：可独立复制安装的 Skill；含教学规则、操作接口、Python 记录模块和面板模板。
- scripts/install_skill.py：安装到用户级 .agents/skills，保存固定课程库路径与 Python 可执行文件位置；已有不同版本默认拒绝覆盖，可显式备份后替换。
- scripts/create_demo.py：建立独立样例，供 T0 和两章流程验证。
- tests：状态、恢复、资料和进程级测试。tests/browser 使用 Chromium 与显式宿主模拟。
- docs/acceptance.md：按 E01–E25 区分自动化证据与待实测项。

课程状态只认一个 course.json。来源与讲义先保存为独立文件，再写入课程引用。新增来源使用新 source_id；章节、题目和依据分别有版本。库中保存上一有效状态备份；损坏时不会自动重置。

讲解和评分由当前 Codex 对话完成，脚本不调用另一个模型。浏览器面板无网络后台，也不直接写文件。所有请求以 JSON 文件进入同一记录接口。保存成功以回读结果为准，非宿主发送回执。

## 与原环境相关的调整

1. Windows 路径从程序中移出，由安装脚本生成绝对路径配置；安装包不携带云环境路径。
2. 文件锁按操作系统选择 flock 或 msvcrt，其他保存逻辑相同。Linux 与 Windows 核心测试均通过，覆盖两进程写入、锁忙重试及注入替换/回读失败；Windows 正常写入及回读另有本机面板记录。
3. 当前云会话无 visualize 渲染工具；用户本机已用 visualize 输出片段，并完成四份带面板标识的请求及保存反馈，覆盖真实换行、中英文引号和代码样文本。生成器同时支持完整静态 HTML 与宿主片段，接入采用已核对文档中的 window.openai 接口。
4. 云开发库与个人正式库分开。不引入云同步或额外后端，也不宣称跨云任务共享学习进度。
5. 核心只用 Python 标准库；PDF 文本提取优先使用 pypdf 6.10.0，或现有 pdftotext。未核对的图形/公式/扫描页保持缺失或待核对，不做自动 OCR 声称。
6. 此前本机运行中聊天通过删除排队消息取消，没有显示发送确认框。修订脚本调整了请求提示和缓存警告，11 项浏览器检查通过；2026-11-04 已正确替换实际调用目录，新面板脚本与修订包内脚本同哈希，原生 UI 复验通过。取消时没有可见回调，面板保留说明取消/重试方式的中性提示，不虚构“已取消”。

## 可复现命令

在仓库根目录：

~~~bash
python -m unittest discover -s tests -v
python -m unittest discover -s tests/browser -v
~~~

浏览器测试需要 requirements-dev.txt 和 Chromium；默认优先使用系统 chromium，也可设置 LEARNER_CHROMIUM。无系统浏览器时使用 Playwright 官方安装：

~~~bash
python -m pip install -r requirements-dev.txt
python -m playwright install chromium
~~~

浏览器测试只临时启动绑定回环地址的文件服务器，结束即关闭；不是产品后台，也不提供对外预览。受管 Chromium 禁止 file 协议，因此测试使用本地 HTTP。
