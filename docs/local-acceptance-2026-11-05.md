## 五个失败与修复范围

| 原项 | 本机发现 | 修复与复验要求 |
| --- | --- | --- |
| E04 Windows Job | 在附加 100 ms 延迟时，实际子进程不在目标 Job；128 MiB 限额仍可申请 192 MiB，结果错误地声称 hard_limit_enforced。5 次无附加延迟对照均拒绝超额分配 | Windows 虚拟环境 redirector 可在父进程被附加 Job 前创建实际解释器。必须先挂起最外层进程、附加并核对 Job 成员/内核限额，再恢复主线程及放行。真实 Windows venv 延迟回归要证明实际工作进程在指定 Job 中，超额分配拒绝，失败时未执行命令 |
| E01 HTML | doctype 被当作已核对的 `html` 正文 | 排除文档类型、声明、处理指令、注释及 head 元数据；有真实正文时只提取正文，只有元数据时明确拒绝 |
| E03 OCR 基准 | OCR 环境缺 `pypdf`；仅隔离补依赖后又被内存预检阻止 | 基准改用已锁定 PDFium/Pillow，不引入 pypdf；在拒绝 pypdf 导入的子进程中验证 10/100 页样本生成与文件释放。内存不足继续独立记录，不能提高预算绕过 |
| B01 样例来源 | 分段平均、分钟换算的计算正确，但讲义引用不覆盖对应推导 | 自编来源补完整推导并按讲义片段和题目绑定准确行号；原有 ID/前 7 行定位保持。新样例使用新隔离库，旧验收库不重新 seed |
| F06 归档提示 | 已恢复课程可离线读；尚未取回归档只说需要恢复，没有说明联网取回 | 从已登记本地副本派生状态：副本存在仅提示“核验后可离线恢复”；未发现则明确需联网取回完整包。Drive 路径/云占位文件不冒充离线副本，完整性仍由恢复流程校验 |
