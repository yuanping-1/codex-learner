# Codex Learner 0.2.0 验收候选

代码覆盖紧凑存储、显式迁移、逐页 OCR、四项学习功能修补、Drive 归档恢复及安装诊断。**2026-11-05 用户提供的本机报告将原候选包判为 FAIL：20 PASS、5 FAIL、12 BLOCKED。** 独立聊天 C04 恢复已报告通过，但不能替代原生面板发送/取消。报告对应 `ed91178` 与 ZIP `3799ba27…e9a60`；本轮修复和后续包的结果必须单独绑定，不能把旧包改判通过。详见 [本机报告与修复映射](local-acceptance-2026-11-05.md)。

以下既有云端自动化、模型资源和 Windows CI 记录属于修订前基线。Windows 的普通启动测试遗漏了虚拟环境 redirector 的延迟启动竞态；其 PASS 不证明任意启动时序都受 Job 约束。修订后的真实 Windows 延迟回归与安装包哈希另行记录。旧版 0.1.0 的本机结果同样不计入新包验收。

## 实测资源

全部数值来自隔离的云端 Linux Python 进程。RSS/工作集与 Windows Job Object 提交内存是不同指标。Codex 客户端和 Google Drive 客户端未测，不合并到 OCR 数字中。

| 测试 | 实测结果 |
|---|---|
| 固定记录数、扩大历史正文 | 正文约 24 KB → 128 MiB，清单仅约 +0.152%；list/review 峰值 12.875 MiB；大正文库短新作答约 15.137 MiB |
| 大量历史 | 1000 作答、1000 评价、1000 帮助事件、20 来源、20 讲义版本、2082 回执；list/review/history 约 30.6–30.9 MiB；submit 约 51.09 MiB |
| 大型 schema 1 迁移 | 72.02 MiB 旧 JSON → 27,895 bytes 清单；增量预览/迁移峰值均约 37.879 MiB，原答与旧备份哈希保持 |
| OCR 10 页 | 593.28 MiB，约 12.36 秒 |
| OCR 100 页 | 618.64 MiB，约 103.86 秒；峰值较 10 页增加约 4.28% |
| 三个连续 PDF | 每次约 462–485 MiB；所有 worker 均确认退出，没有残留已观察进程 |
| 原 PDF 局部重读 | 300 DPI 请求在像素约束下重新渲染，约 539 MiB，保留原坐标；结果仍待视觉核对 |

OCR 测试使用自行编写的中英数字扫描页；10/100 页使用重复同类页检验资源规模，不是复杂文档识别准确率基准。2 GiB 是默认工程预算，不能据此承诺所有 Docling 模型可运行。

写入前会流式核验历史附件以保护最后有效备份，因此写入时间随历史字节数增加。大正文样本中短新作答约 0.147 秒；大量历史样本约 1.385 秒。这些是单次样本，不能作为吞吐量或时延分位数承诺。

## 最终包证据

发布包的 `BUILD.json` 保存版本、来源提交、读取/写入 schema 和源文件清单哈希；`MANIFEST.sha256.json` 逐文件校验。包外的 `release-verification.json` 绑定最终 ZIP SHA-256、测试结果和本页证据文件哈希，避免把另一版本测试结果当成该包验收。

安装包不内嵌模型、课程、凭据或用户配置。`scripts/package.py` 在源文件变化时拒绝发布不一致包。详情和操作步骤见 [升级说明](v0.2-upgrade.md)。
