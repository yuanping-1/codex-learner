## 源码审查与可复现缺口

云端检查 `7946513` 的恢复实现，目录重命名分别用于搬移释放残留、启用课程及两次回滚。现有摘要未给出失败所在步骤，**不能认定 Windows 拒绝访问的根因**。正常路径的 ZIP、解包输出和哈希句柄在移动前已关闭；父目录 `.library.lock` 不随课程移动，没有证据可据此断言自己的句柄泄漏或杀毒软件占用。

三个 Linux 隔离故障注入只证明异常控制流：

1. 发布目录失败：调用失败，暂存目录被清理，原 ZIP 保留，之后恢复可以成功。
2. 发布失败后回滚也失败：第二个异常掩盖第一个；暂存现场被自动清理，索引仍阻止启用，原有效 ZIP 保留。不能据此声称永久丢失课程。
3. 恢复提交成功后清理失败：调用报错，但课程已可读取、归档索引已移除，再次恢复返回 `course_exists`。

当前修订针对这些确定的异常处理和可观测性缺口：区分移动、索引与清理阶段；保留原错误及回滚结果；回滚失败或提交状态不明时保留暂存材料；成功提交后清理失败回读状态并报告已启用及警告。没有依据外部占用的猜测增加自动重试，也没有宣称上述注入复现了用户的 `WinError 5`。

独立补审还确认了提交后解锁失败的状态误报；当前实现返回 `commit_uncertain`、标明 `unlock_library` 并保留现场，避免把可能已启用的课程称为未恢复。清理部分执行时，诊断也区分暂存目录确实存在、不存在和未能确认。
